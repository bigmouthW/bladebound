## 2 启动

当前工作区的本地服务地址为 [http://127.0.0.1:4173](http://127.0.0.1:4173)。本次服务与验证没有在用户桌面打开游戏窗口。

服务退出后，在项目根目录执行：

```powershell
npm ci
npm run dev -- --port 4173
```

使用 Node.js 22 或兼容版本。安装依赖需要网络，游戏资源全部来自本地。上述命令不会自动打开浏览器；端口被占用时换用可用端口。

生产构建与本地预览：

```powershell
npm run build
npm run preview -- --port 4175
```

生产文件位于 dist，需要 HTTP 静态服务。直接双击 index.html 不能正确加载 ES Modules 和资源。资源路径已改为相对路径（vite.config.js 中 `base: './'`），同一份构建既可从站点根目录运行，也可放在任意子目录或第三方游戏平台上。

## 3 操作

| 操作 | 输入 |
| --- | --- |
| 开始 | 选择标准或轻松，再点击开始试炼 |
| 翻跃 | 点击画面、触摸画面、翻跃按钮或空格 |
| 再次翻跃 | 空中再次按下，重置竖直速度 |
| 切割与攻击 | 刃口接触物体或敌人自动触发 |
| 蓄能斩 | 能量满后，下一次命中敌人自动释放 |
| 暂停与继续 | 暂停按钮、P 或 Escape |
| 关间选择 | 第一关、第二关完成后，各选择一项强化 |
| 重试 | 失败或暂停画面中的重试本关 |
| 本地设置 | 顶部设置入口；支持声音与减少动态效果 |
| 语言 | 开始界面的 English / 中文，或设置中的 Language / 语言菜单 |
| 外观与纪录 | 顶部刀具、奖杯图标 |

按住不连续翻跃。跌落会扣除护盾并返回最近行灯，护盾耗尽后进入失败；重试本关会保留已选强化和此前完成关卡的金币。

## 4 已实现范围

三关分别为竹影初行、赤桥追风、山门决意，共 12 个手工段落、78 个可切物、24 名敌人，其中包含一个最终首领。

| 系统 | 原型行为 |
| --- | --- |
| 物理与输入 | Matter.js 固定 120 Hz 更新；键鼠与触摸共用翻跃动作 |
| 切割 | 红果、青梨、木箱，连斩计分和切片刚体 |
| 战斗 | 普通攻击、满能量蓄能斩、盾牌、重型敌人、首领和断箭 |
| 布娃娃 | 敌人死亡后转为六个刚体、五个约束组成的布娃娃 |
| 关卡 | 尖刺、缺口、高位分路、每关中段检查点 |
| 强化 | 六种效果，各两级；两次关间三选一 |
| 经济 | 完成关卡结算金币，六种刀柄与尾迹配色 |
| 状态 | 准备、运行、暂停、失败、强化、最终结算 |
| 保存 | 金币、外观、最佳得分、累计统计和偏好保存在当前浏览器 |
| 语言 | 默认英语，英语与简体中文可即时切换，包含全部界面与画布文字 |

刷新不会恢复进行中的关卡。存档以浏览器和站点地址区分，更换浏览器、端口或清理站点数据会出现新的进度。

## 5 验证方法

基础逻辑检查：

```powershell
npm test
```

浏览器与连续闯关检查需要先启动开发服务。默认连接 4173，可用 BLADEBOUND_URL 指定另一个地址。

已有 Chromium 系浏览器时可直接指定路径，无需安装测试浏览器。本机验证使用以下命令：

```powershell
$env:BLADEBOUND_BROWSER='C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
npm run test:browser
npm run test:playthrough
npm run test:i18n
```

也可安装 Playwright 自带的无界面浏览器：

```powershell
npx playwright install chromium --only-shell
npm run test:browser
npm run test:playthrough
npm run test:i18n
```

浏览器脚本均显式使用 headless: true，不会在桌面打开游戏窗口。测试报告和截图写入 test-results，重复执行会覆盖同名结果。

## 6 已知边界

- 活体敌人使用固定姿态和射击预告，只有死亡后使用关节物理；尚无完整拉弓骨架动画。
- 三条高位路线均有实现与碰撞验收，连续试跑主要沿主路线完成，没有覆盖所有路线与强化组合。
- 外观只影响配色，尚未制作独立刀型；声音为 Web Audio 合成短音，没有正式背景音乐。
- 自动旋转会影响命中与断箭，具体手感和容错仍需真人试玩调整。
- 当前移动端结果来自浏览器视口和触摸模拟，尚未代表全部手机硬件与 Safari 实机表现。
- 没有广告、支付、账号、云存档、排行榜后端和遥测；没有验证商业运营指标。

## 7 后续开发顺序

1. 先观察真人首轮切割、首个障碍与首个持盾敌人的操作，调整预告、跳跃容错和攻击节奏。
2. 分别记录标准、轻松难度的完成情况和每个危险点的失败分布，再调参数。
3. 检查高位分路和六种强化的实际收益，完善缺少使用场景的组合。
4. 完善活体动画、音源和更多手工段落后，再接入目标平台 SDK。
